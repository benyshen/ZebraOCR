## 1. 项目概述

### 1.1 项目目标

开发一款 Windows 桌面软件：用 Zebra DS8288 扫码枪捕获图像，交给本地部署的 AI 大模型（百度 Unlimited-OCR）做 OCR 文字识别，并在界面中展示识别结果。

### 1.2 硬件组成

| 设备 | 型号 | 说明 |
|---|---|---|
| 手持扫码枪 | Zebra DS8288-SR4F004VZWW | 无线手持枪，负责拍照/扫条码，SN=25269525180446 |
| 底座 | Zebra CR8288-PC100F4WW | 无线底座，通过 USB 连接电脑，SN=25267525180198 |
| 显卡 | NVIDIA RTX A500 Laptop 4GB | 运行 OCR 模型（NF4 4-bit 量化） |

> **重要**：DS8288 是无线手持枪，电脑 USB 端只连接 CR8288 底座。
> 拍照图像通过「手持枪 → 底座 → USB → 电脑」传输，CoreScanner 中会同时出现两台设备。

### 1.3 软件组成

- **ZebraOCR.exe**（C# WPF）：主界面 + 扫码枪控制。
- **ocr_server.py**（Python）：本地 HTTP 服务，封装 Unlimited-OCR 模型推理。
- **CoreScanner.dll**（Zebra COM 互操作）：访问 Zebra 扫码枪。

### 1.4 核心流程

```text
用户点击「扫码并OCR识别」
  → 程序发送 DEVICE_CAPTURE_IMAGE(3000) 到底座，进入图像模式
  → 提示用户扣动扳机
  → 手持枪拍照，图像经底座传回 → 触发 ImageEvent
  → C# 收到图像字节 → 左侧预览
  → 保存临时 JPG → POST http://127.0.0.1:5100/recognize
  → ocr_server.py 调用 Unlimited-OCR 推理（约 60~90 秒）
  → 返回识别文本 → 右侧文本框展示
```

## 4. 软件使用方法

### 4.1 启动前置条件

1. Zebra CoreScanner Driver 已安装（Windows 11 无需单独装驱动）。
2. 扫码枪底座（CR8288）已通过 USB 连接电脑，手持枪（DS8288）已与底座配对。
3. OCR 模型目录存在：`D:\AI\OCR-Scane\Unlimited-OCR`。
4. Python 环境已安装依赖（见第 8 节）。

### 4.2 启动步骤

```powershell
# 方式一：直接运行发布版
D:\AI\OCR-Scane\ZebraOCR\publish\ZebraOCR.exe

# 方式二：先手动启动 OCR 服务，再运行程序（程序检测到端口已占用会直接复用）
C:\Python314\python.exe D:\AI\OCR-Scane\ZebraOCR\ZebraOCR\ocr_server.py --port 5100
D:\AI\OCR-Scane\ZebraOCR\ZebraOCR\bin\Debug\net8.0-windows\ZebraOCR.exe
```

启动后约 30~60 秒模型加载完成，状态栏显示「OCR 模型已就绪（Unlimited-OCR）」。

### 4.3 操作步骤

1. 在下拉框选择扫码枪：**建议选择 `[底座] CR8288`**（ID:1），图像必须通过底座传输。
   - 如果选择了手持枪，程序会自动同时 Claim 底座，拍照时自动把图像命令发往底座。
2. 点击「连接扫码枪」，按钮变为「断开连接」，表示已连接。
3. 点击「扫码并OCR识别」，界面提示「请拿起手持扫码枪，对准目标扣动扳机」。
4. **拿起 DS8288 手持枪，对准要识别的文字，扣动扳机**。
5. 左侧出现预览图像，右侧等待约 60~90 秒后显示 OCR 识别文字。
6. 可重复步骤 3~5 多次识别，结果会带序号和时间戳追加显示。

### 4.4 首次使用（图像模式切换）

如果点击「扫码并OCR识别」后提示命令失败（如 opcode:3000, status:119），或扫码枪从未支持图像传输，请先点击「切换图像模式」：

1. 点击「切换图像模式」按钮。
2. 确认弹窗后，程序发送配置码 `XUA-45001-9`（USB-SNAPI with Imaging）。
3. 等待约 10 秒设备重新枚举，程序自动重新发现设备。
4. 重新选择底座并连接。

> 配置码来源：官方示例 `ScannerAction.cs` 中 `HostModes` 字典：
> - `USB-HIDKB` = `XUA-45001-3`
> - `USB-IBMHID` = `XUA-45001-1`
> - `USB-SNAPI with Imaging` = `XUA-45001-9`（图像模式，本程序使用）
> - `USB-SNAPI without Imaging` = `XUA-45001-10`

## 5. OCR 模型（Unlimited-OCR）部署与使用

### 5.1 模型简介

- **名称**：baidu/Unlimited-OCR（官方名 "Unlimited OCR Works"）
- **主页**：https://huggingface.co/baidu/Unlimited-OCR
- **代码**：https://github.com/baidu/Unlimited-OCR
- **论文**：https://arxiv.org/abs/2606.23050
- **定位**：DeepSeek-OCR 的进阶版，多语言、单图一次性长跨度解析（One-shot Long-horizon Parsing）
- **License**：MIT
- **能力**：文档解析、版面理解、多页 PDF、手写体、复杂版面

### 5.2 本地模型文件（D:\AI\OCR-Scane\Unlimited-OCR）

| 文件 | 大小 | 说明 |
|---|---|---|
| model-00001-of-000001.safetensors | 6.67GB | 模型权重（单分片 safetensors） |
| modeling_unlimitedocr.py | 55KB | 模型自定义代码（trust_remote_code 加载） |
| modeling_deepseekv2.py / deepencoder.py / conversation.py | - | 依赖的自定义模块 |
| tokenizer.json | 10MB | 分词器 |
| tokenizer_config.json / config.json / processor_config.json | - | 配置 |
| special_tokens_map.json | - | 特殊 token |
| README.md / LICENSE / Unlimited-OCR.pdf | - | 说明与论文 PDF |
| wheel\ | - | SGLang 推理 wheel（可选，本程序未用） |

### 5.3 官方推理参数（来自模型 README）

单图有两种配置：

```python
# gundam 模式（推荐，本程序使用）：图像切块增强小字识别
base_size=1024, image_size=640, crop_mode=True

# base 模式：整图解析
base_size=1024, image_size=1024, crop_mode=False
```

多页 / PDF 用 `infer_multi()`（image_size=1024）。

本程序 `ocr_server.py` 使用 **gundam** 模式 + `max_length=8192`（C# 端）或 32768（默认），
`no_repeat_ngram_size=35, ngram_window=128`。

### 5.4 模型加载策略（ocr_server.py 自动选择）

```python
def pick_load_strategy(force_cpu=False):
    - 无 GPU / --force-cpu  → CPU 加载（慢）
    - 显存 >= 8GB          → BF16 全量加载
    - 显存 <  8GB          → 4-bit NF4 量化（本机 4GB 走此分支）
```

本机（RTX A500 4GB）实际加载：NF4 4-bit，显存约 2~3GB，加载约 27 秒。

### 5.5 独立启动 OCR 服务

```powershell
# 默认端口 5100
C:\Python314\python.exe D:\AI\OCR-Scane\ZebraOCR\ZebraOCR\ocr_server.py

# 指定端口 / 模型路径 / CPU 模式
C:\Python314\python.exe D:\AI\OCR-Scane\ZebraOCR\ZebraOCR\ocr_server.py --port 5100 --model D:\AI\OCR-Scane\Unlimited-OCR
C:\Python314\python.exe D:\AI\OCR-Scane\ZebraOCR\ZebraOCR\ocr_server.py --force-cpu
```

启动后：
- 后台线程加载模型（约 30~60 秒）
- HTTP 服务监听 `0.0.0.0:5100`

### 5.6 HTTP API

**GET /health** —— 健康检查

```json
{
  "status": "ok",
  "model_loaded": true,
  "device": "cuda",
  "load_progress": "loaded",
  "error": null
}
```

**POST /recognize** —— 图像识别

请求 JSON：

```json
{
  "image_path": "D:/path/to/image.jpg",
  "prompt": "<image>document parsing.",
  "image_mode": "gundam",
  "max_length": 8192
}
```

| 字段 | 默认值 | 说明 |
|---|---|---|
| image_path | 必填 | 本地图像绝对路径（jpg/png） |
| prompt | `<image>document parsing.` | 任务提示词 |
| image_mode | `gundam` | `gundam`（切块增强）或 `base`（整图） |
| max_length | 32768 | 最大生成长度 |

响应 JSON：

```json
{ "success": true, "result": "识别出的文本...", "elapsed_sec": 86.77 }
```

错误响应：`{ "success": false, "error": "错误信息" }`（400/500/503）。

### 5.7 调用示例（PowerShell）

```powershell
$body = '{"image_path":"D:\\AI\\OCR-Scane\\OCR_Sample.jpeg","prompt":"<image>document parsing.","image_mode":"gundam","max_length":8192}'
[System.IO.File]::WriteAllText('D:\AI\OCR-Scane\req.json', $body, (New-Object System.Text.UTF8Encoding($false)))
Invoke-RestMethod -Uri 'http://127.0.0.1:5100/recognize' -Method Post `
  -ContentType 'application/json; charset=utf-8' -InFile 'D:\AI\OCR-Scane\req.json' -TimeoutSec 300
```

### 5.8 识别耗时参考

| 环境 | 单图耗时 |
|---|---|
| RTX A500 4GB（NF4 量化） | 约 60~90 秒 |
| 8GB+ 显卡（BF16 全量） | 预计 20~40 秒 |
| CPU | 数分钟（不推荐） |

## 7. CoreScanner SDK 集成说明

> 官方文档：https://techdocs.zebra.com/dcs/scanners/sdk-windows/about/

### 7.1 SDK 概述

Zebra CoreScanner SDK（Windows）是 Zebra 官方提供的扫描器开发套件，通过 **COM 组件**（`CoreScanner.dll`）与电脑上运行的 **CoreScanner 服务**（随 CoreScanner Driver 安装，Windows 11 自带）通信，统一管理 USB / 串口 / 蓝牙等连接方式的 Zebra 扫描器。

SDK 能力（本程序用到的部分）：

- 枚举当前接入的扫描器（`GetScanners`）
- 注册/注销事件（`RegisterForEvents` / `UnregisterForEvents`）
- 声明设备独占（`Claim` / `Release`）
- 向设备下发指令（`ExecCommand`），如拍照、切模式、拉扳机
- 接收设备上报事件：条码（BarcodeEvent）、图像（ImageEvent）、视频（VideoEvent）、热插拔（PNPEvent）

### 7.2 程序中的引用方式

C# 侧通过 `Interop\CoreScanner.dll`（TLB 互操作程序集）引入：

```csharp
using CoreScanner;
private CoreScannerClass m_pCoreScanner = new CoreScannerClass();
```

工程文件 `ZebraOCR.csproj` 中的引用：

```xml
<Reference Include="CoreScanner" HintPath="Interop\CoreScanner.dll" />
```

> 注意：CoreScanner 服务必须已启动（安装了 CoreScanner Driver 后自动运行）。程序启动时会先 `Open`，失败则状态栏提示。

### 7.3 核心接口与方法

| 方法 | 签名（互操作） | 说明 |
|---|---|---|
| `Open` | `Open(int appHandle, short[] scannerTypes, short numberOfTypes, out int status)` | 打开与 CoreScanner 服务的连接；`scannerTypes` 传 `{ 1 }`（全部类型） |
| `GetScanners` | `GetScanners(out int numberOfScanners, int[] scannerIdList, out string outXML, out int status)` | 枚举设备，返回 XML 格式的设备清单 |
| `ExecCommand` | `ExecCommand(int opcode, ref string inXml, out string outXml, out int status)` | 向设备执行命令，`inXml` 为参数 XML |
| `RegisterForEvents` | `RegisterForEvents(int eventType, string appHandle, out int status)` | 订阅事件，`eventType` 为位掩码 |
| `UnregisterForEvents` | `UnregisterForEvents(int eventType, string appHandle, out int status)` | 取消订阅 |
| `Close` | `Close(int appHandle, out int status)` | 关闭连接 |

`appHandle` 是窗口句柄（`IntPtr`），用于事件回调路由。

### 7.4 事件模型

事件通过 **位掩码** 订阅（`SUBSCRIBE_*` 常量），本程序订阅了条码+图像+热插拔：

```csharp
private const int SUBSCRIBE_BARCODE = 1;   // 条码事件
private const int SUBSCRIBE_IMAGE   = 2;   // 图像事件
private const int SUBSCRIBE_VIDEO   = 4;   // 视频事件（未使用，可扩展）
private const int SUBSCRIBE_RMD     = 8;   // 远程管理数据
private const int SUBSCRIBE_PNP     = 16;  // 即插即用（热插拔）
private const int SUBSCRIBE_OTHER   = 32;  // 其他事件
```

C# 事件回调接口（互操作自动生成）：

```csharp
m_pCoreScanner.BarcodeEvent   += new _ICoreScannerEvents_BarcodeEventHandler(OnBarcodeEvent);
m_pCoreScanner.ImageEvent     += new _ICoreScannerEvents_ImageEventHandler(OnImageEvent);
m_pCoreScanner.PNPEvent       += new _ICoreScannerEvents_PNPEventHandler(OnPNPEvent);
```

各回调的 data 参数为 XML 字符串：

| 事件 | 回调签名 | data 关键字段 |
|---|---|---|
| BarcodeEvent | `(short eventType, ref string pscanData)` | `<scannerID>`、`<datalabel>`（十六进制条码）、`<datatype>` |
| ImageEvent | `(short eventType, ref string pscanData)` | `<scannerID>`、`<data>`（Base64 图像字节） |
| PNPEvent | `(short eventType, ref string pscanData)` | `<scannerID>`、`<scannerPNP>`、`<scannerStatus>`（0=插入） |

ImageEvent 中 `eventType == 1` 表示单张图像捕获完成（`IMAGE_COMPLETE`）。

### 7.5 Opcode 指令表（本程序使用的）

| 常量名 | Opcode | 说明 |
|---|---|---|
| `REGISTER_FOR_EVENTS` | 1001 | 注册事件 |
| `UNREGISTER_FOR_EVENTS` | 1002 | 注销事件 |
| `CLAIM_DEVICE` | 1500 | 声明设备独占（连接后必须） |
| `RELEASE_DEVICE` | 1501 | 释放设备 |
| `DEVICE_PULL_TRIGGER` | 2011 | 拉扳机触发（对无线枪无效，未作为主流程） |
| `DEVICE_CAPTURE_IMAGE` | 3000 | **拍照（本程序核心）** |
| `DEVICE_SWITCH_HOST_MODE` | 6200 | 切换主机模式（切换图像模式时使用） |

状态码：`0` = 成功（`STATUS_SUCCESS`），`1` = 失败（`STATUS_FALSE`）。命令失败时状态栏显示 `status:<码>`。

### 7.6 XML 参数格式

所有命令参数以 XML 字符串传入 `ExecCommand` 的 `inXml`：

```xml
<!-- 拍照：scannerID 必须是图像回传的设备（本程序为底座 ID:1） -->
<inArgs><scannerID>1</scannerID></inArgs>

<!-- Claim / Release 设备 -->
<inArgs><scannerID>2</scannerID></inArgs>

<!-- 切换主机模式：USB-SNAPI with Imaging（配置码 XUA-45001-9） -->
<inArgs>
  <scannerID>2</scannerID>
  <scannerConfig>
    <configString>XUA-45001-9</configString>
  </scannerConfig>
</inArgs>
```

`GetScanners` 返回的设备 XML 形如：

```xml
<scanners>
  <scanner>
    <scannerID>2</scannerID>
    <scannername>DS8288-SR4F004VZWW</scannername>
    <serialnumber>25269525180446</serialnumber>
    <model>DS8288</model>
    <guid>...</guid>
    <port>USB</port>
    <firmware>...</firmware>
  </scanner>
</scanners>
```

### 7.7 图像捕获流程（与官方 Demo 的差异）

官方 Demo（`Scanner-SDK-for-Windows-master`）用 `DEVICE_CAPTURE_IMAGE` 对**单台有线设备**拍照。本程序是**无线手持枪 + 底座**组合，关键差异：

1. CoreScanner 中会出现两台设备：手持枪（ID:2）与底座（ID:1）。
2. **图像命令必须发给底座**（ID:1），发手持枪会返回 `status:119` 失败。
3. 程序连接手持枪时会自动同时 Claim 底座，拍照时自动把命令转发到底座。
4. 触发方式依赖用户**真实扣动扳机**（`PULL_TRIGGER` 对无线枪无效），程序等待 `ImageEvent` 最多 30 秒。
5. 收到图像后，C# 侧把 Base64 解码为字节数组，存为临时 JPG 交给 OCR。

官方 SDK 文档中「图像捕获与传输」章节（Image Capture and Transport）对应本程序的第 5、6 步：`DEVICE_CAPTURE_IMAGE`（3000）→ ImageEvent → `<data>` Base64 → 解码保存。

## 9. 遇到的问题与解决方案

本章记录开发与调试过程中遇到的实际问题及解决办法，供后续维护参考。

### 9.1 界面中文显示乱码（？？？？）

**现象**：编译运行后界面按钮、标签全部显示为 `？？？？`。

**原因**：编译产物是旧版本/未重新编译，或 XAML 资源文件编码损坏导致中文字符串未正确编译进程序集。

**解决**：删除 `bin`、`obj` 目录后重新编译：

```powershell
cd D:\AI\OCR-Scane\ZebraOCR
Remove-Item -Recurse -Force ZebraOCR\bin, ZebraOCR\obj
dotnet build -c Debug
```

发布版使用 `dotnet publish` 重新生成后界面中文正常。

### 9.2 图像命令发手持枪返回 status:119

**现象**：对手持枪（DS8288，ID:2）执行 `DEVICE_CAPTURE_IMAGE(3000)` 返回 `status:119`，拍照失败。

**原因**：DS8288 是无线手持枪，USB 端只连接 CR8288 底座。图像数据流是「手持枪 → 底座 → USB → 电脑」，**图像捕获命令必须发给底座（ID:1）**；底座负责把成像指令转发给手持枪并把图像回传。

**解决**：程序自动处理——连接时若选中手持枪，自动同时 Claim 底座；拍照时把命令的 `<scannerID>` 改为底座 ID。若下拉框选择底座则直接使用。

### 9.3 PULL_TRIGGER 对无线枪无效

**现象**：调用 `DEVICE_PULL_TRIGGER(2011)` 想远程触发拍照，无线枪无反应。

**原因**：无线（Wireless）模式下手持枪不在电脑的 USB 总线上，`PULL_TRIGGER` 只能作用于底座直连的有线扫描器，无法唤醒无线枪的扳机电路。

**解决**：放弃远程触发，改为**依赖用户真实扣动扳机**。程序发送 `DEVICE_CAPTURE_IMAGE` 进入成像模式后提示「请拿起手持扫码枪，对准目标扣动扳机」，然后阻塞等待 `ImageEvent`（最长 30 秒）。用户扣扳机即可拍照，实测稳定可靠。

### 9.4 Python 进程 GBK 编码崩溃（U+2611 ☑）

**现象**：`ocr_server.py` 启动后立刻抛 `UnicodeEncodeError`，涉及字符 `U+2611 ☑`（模型加载进度输出），程序 OCR 服务无法就绪。

**原因**：Windows 控制台默认代码页 GBK（cp936），Python `print` 输出含 GBK 无法编码的字符时直接崩溃。

**解决**：在 `ocr_server.py` 头部强制把 stdout/stderr 重配置为 UTF-8 并容错：

```python
import sys
if hasattr(sys.stdout, 'reconfigure'):
    sys.stdout.reconfigure(encoding='utf-8', errors='replace')
    sys.stderr.reconfigure(encoding='utf-8', errors='replace')
```

### 9.5 PowerShell 写中文文件乱码

**现象**：用 `Set-Content` / `Out-File` 写含中文的 `.py` / `.md` 文件出现乱码。

**原因**：PowerShell 5.1 默认编码不是 UTF-8（而是本地 ANSI），中文被错误编码。

**解决**：写中文内容一律使用 UTF-8 编码，例如：

```powershell
$text = '中文内容...'
Add-Content -LiteralPath 'D:\AI\OCR-Scane\ZebraOCR\开发文档.md' -Value $text -Encoding UTF8
```

> 若使用 here-string 批量写入，注意闭合符必须单独成行，且内容里不要出现独立的闭合符行，否则会提前终止字符串。

### 9.6 exe 运行中编译失败（文件被占用）

**现象**：`dotnet build` 报错 `ZebraOCR.exe ... is being used by another process`。

**原因**：程序（或发布版）还在运行，输出文件被锁定。

**解决**：先结束进程再编译：

```powershell
Get-Process ZebraOCR -ErrorAction SilentlyContinue | Stop-Process -Force
# 或同时清理 python 子进程
Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force
dotnet build -c Debug
```

### 9.7 首次点击「扫码并OCR识别」无反应/提示命令失败

**现象**：设备未处于成像模式（SNAPI with Imaging），命令执行失败。

**解决**：点击「切换图像模式」按钮，程序发送配置码 `XUA-45001-9`（USB-SNAPI with Imaging），设备重新枚举约 10 秒后自动重连。之后拍照命令即可正常执行。

### 9.8 OCR 耗时较长（60~90 秒/张）

**原因**：4GB 显存只能 NF4 4-bit 量化加载，推理速度受限；`gundam` 模式（base_size=1024、image_size=640、crop_mode=True）需要较长处理链。

**解决**：属正常现象，界面状态栏会显示进度。若需提速可升级更大显存显卡，或改用更小的输入尺寸/关闭 crop。

```csharp
// 中文优先 + 结构化输出
prompt = "<image>识别图中全部中文文字，保留换行与版面顺序。";
```

`RecognizeAsync` 的第二个参数 `prompt` 可对单次调用临时覆盖。

### 10.3 增加视频预览（VideoEvent）

CoreScanner 支持视频流（预览取景）。步骤：

1. 订阅视频事件：`RegisterForEvents` 的 eventType 加上 `SUBSCRIBE_VIDEO(4)`。
2. 添加回调 `m_pCoreScanner.VideoEvent += ...`，解析 `<data>` Base64 帧并刷新 `Image` 控件。
3. 用 `DEVICE_CAPTURE_VIDEO(4000)` 开始视频、`DEVICE_STOP_VIDEO(4001)` 停止。

> 注意：视频流与图像模式互斥，拍照前需先停止视频。

### 10.4 保存图像 / 导出识别结果

当前图像已缓存在 `m_lastImageBytes`，可增加按钮：

```csharp
// 保存图像
File.WriteAllBytes(@"D:\OCR\captures\" + DateTime.Now.ToString("yyyyMMdd_HHmmss") + ".jpg", m_lastImageBytes);

// 导出识别结果（TextBox 内容）
File.WriteAllText(@"D:\OCR\results.txt", tbOcrResult.Text, Encoding.UTF8);
```

### 10.5 批量扫描

在 `btnCaptureOCR_Click` 主流程外包一层循环：

1. 增加「连续扫描 N 张」配置（NumericUpDown 或下拉框）。
2. 每轮：发拍照命令 → 等 ImageEvent（30 秒）→ OCR → 结果带序号追加。
3. 加「停止」标志位，循环中检查，支持中断。
4. 注意 OCR 单张 60~90 秒，批量时总耗时较长，建议用 `Task` + 进度条。

### 10.6 多底座 / 多枪支持

`DiscoverScanners()` 已返回全部设备。扩展思路：

- 下拉框分组：按底座分组显示其关联手持枪。
- 建立「底座 ↔ 手持枪」映射：通过扫描器 GUID/序列号前缀（CR8288 与 DS8288 同属一套）关联。
- 拍照时始终把命令发给对应底座 ID，底座 ID 从映射中取。

### 10.7 对接数据库 / 导出系统

在 `AppendOcrResult` 处插入持久化逻辑：

```csharp
// 示例：SQLite / SQL Server / MySQL 均可
INSERT INTO ocr_records (scanner_id, image_path, result_text, created_at) VALUES (@id, @img, @text, @time);
```

推荐把「识别结果 + 图像路径 + 时间戳」作为一条记录保存，便于追溯。

### 10.8 性能优化方向

| 方向 | 做法 |
|---|---|
| OCR 提速 | 更大显存显卡 / 关闭 crop / 缩小 image_size |
| 并行识别 | 多请求排队（当前为单模型串行，避免显存 OOM） |
| 模型热切换 | 预加载多个模型，按图片类型路由 |
| 图像压缩 | 上传前压缩为 JPEG quality=85，减少传输/内存 |

发布参数说明：

### 11.3 发布目录内容

```text

├── ZebraOCR.dll / ZebraOCR.runtimeconfig.json
├── CoreScanner.dll              # Zebra COM 互操作
├── Newtonsoft.Json.dll
├── ocr_server.py                # OCR 服务脚本（随程序分发）
└── Interop\CoreScanner.dll
```

> 注意：发布目录必须包含 `ocr_server.py`（csproj 中配置了 `CopyToOutputDirectory="PreserveNewest"`），否则程序找不到 OCR 服务脚本。

### 11.4 部署到目标电脑

1. 拷贝整个 `publish` 目录到目标电脑。
2. 目标电脑安装：
   - .NET 8（或 10）桌面运行时（`--self-contained false` 时需要）。
   - Python 3.14 + 第 8 节全部依赖（或直接用已装好环境的机器）。
   - Zebra CoreScanner Driver（Windows 11 自带，无需安装）。
3. 确认模型目录存在：`D:\AI\OCR-Scane\Unlimited-OCR`（可在 `ocr_server.py` 用 `--model` 改路径）。
4. 运行 `ZebraOCR.exe`。

### 11.5 OCR 服务自动启动逻辑

程序启动时 `OCRService.InitializeAsync()` 自动处理服务生命周期：

1. 探测 Python（`C:\Python31x\python.exe` → `where python`）。
2. 探测 `127.0.0.1:5100` 端口：
   - 已被占用（例如手动启动过）→ **直接复用**，不重复启动。
   - 未被占用 → 以子进程拉起 `ocr_server.py --port 5100`。
3. 轮询 `/health` 直到 `model_loaded=true`（最长 180 秒），期间状态栏显示加载进度。
4. 程序退出时 `Dispose()` 杀掉自己拉起的子进程；手动启动的服务不受影响。

这样用户无需手动开终端，双击 exe 即可全流程使用。

### 11.6 版本升级

1. 修改源码后执行 11.2 的 publish 命令。
2. 覆盖目标电脑 publish 目录中的文件（exe/dll/py 均可热替换，无需重装）。
3. 若模型或 Python 依赖有变化，需同步更新目标电脑环境。
